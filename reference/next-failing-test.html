The next failing test

After one honest pass, write one new failing test of the tracer you already named. Existing tests stay green. The rest of the list stays a list.

The loop (this lesson)

  1. You already have one failing test that you made pass with only enough code.
  2. Look at the tracer you named. Which observation still has no failing test?
  3. Turn that one item into a runnable test at a public seam.
  4. Watch it fail for a real reason. Tests you already had keep passing.
  5. Write only enough product code to pass the new test. The rest of the list stays notes.

Beck, Canon TDD, step 5. Cleaning up the code after a pass is a later lesson. Picking the best order of tests, beyond “the next missing piece of the tracer,” is also later.

Which next move

Move What it verifies
Turn the leftover cases into tests Imagined behaviour. The same bulk-suite mistake, one cycle later.
Build the rest of the feature Code no new test asked for. The same extra-feature mistake, one cycle later.
One next failing test of the tracer Observed behaviour. Earlier tests stay green. Distant cases stay on the list.

The next test looks like

  • Names a missing piece of the tracer you already wrote (for Handbook Ask, the page).
  • Calls a public seam. Does not rewrite the tests you already had.
  • Expected values are still literals you chose, not values pasted from a run.
  • Fails before the new product code exists. Earlier tests keep passing.
[Fact]
public async Task Ask_page_shows_i_dont_know()
{
    var page = await client.GetAsync("/");
    // submit the question on the page; read the result
    Assert.Contains("I don't know", body);
}

Done when

  • You can point at the new test and say how it failed, while earlier tests stayed green.
  • The next case was a missing piece of the named tracer, not a distant item from the list.
  • Other cases are still a list, not extra tests and not extra code.
  • An agent was told: one next failing test; existing tests stay green; do not implement the list.

Agent prompt shape

The first test is green. Do not edit it.

Write ONE next failing test of this tracer:
the missing piece is [page / auth / lookup].
Show me the red output. Existing tests must stay green.
Then write only enough code to pass it.
Still on the list (not tests yet): [cases].
