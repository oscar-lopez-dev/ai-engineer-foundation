One failing test

The first coding step on a tracer. A list of cases is not a suite of tests. The test must fail before you write product code.

The loop (this lesson)

  1. You already have a tracer you would keep.
  2. Jot a test list — cases, not code. (Beck’s step 1.)
  3. Turn exactly one item into a runnable test at a public seam.
  4. Watch it fail for a real reason (no route, wrong body) — not because the test is broken.
  5. Write only enough product code to pass that test. (Lesson 0004 practises this step.)
  6. Then write the next failing test of the tracer. (Lesson 0005.)

Beck, Canon TDD. Cleaning up the code after the test passes is a later lesson. Mocking internal collaborators is also later.

Which first move

Move What it verifies
Implement, then add tests A record of whatever was already built. You never confirmed that the test can fail.
Write every test, then implement Imagined behaviour. Speculative tests break when the first pass teaches you something.
One failing test of the tracer, then code Observed behaviour. The next case stays on the list.

The first test looks like

  • Names the tracer: who / what / the observation (“I don’t know”, 200, refused).
  • Calls a public seam (HTTP API or the page), not a private method.
  • Expected values are literals you chose, not values pasted from a passing run.
  • Fails before the product code exists.
[Fact]
public async Task Ask_seeded_pdf_says_i_dont_know()
{
    var res = await client.PostAsJsonAsync(
        "/api/ask", new { question = "What is the leave policy?" });
    var body = await res.Content.ReadAsStringAsync();
    Assert.Equal(HttpStatusCode.OK, res.StatusCode);
    Assert.Contains("I don't know", body);
}

Done when

  • You can point at the one test and say how it failed before you wrote the product code.
  • The implementation you (or the agent) wrote is the smallest path that makes that test pass.
  • Other cases are still a list, not test files.
  • An agent was told: one failing test of this tracer, no suite, do not implement first.

Agent prompt shape

This is a TRACER (keep it):
[who] can [do X] and [see Y], or [named failure].

TDD — do not implement yet:
1. Write ONE failing test of that path at [seam].
2. Show me the red output.
3. Then write only enough code to pass it.
Still on the list (not tests yet): [cases].

Related, later
