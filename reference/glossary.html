Reference

Glossary

The words this course uses on purpose. Prefer these in tickets, prompts, and reviews.

Delivery

Horizontal layer. A unit of work named after a technical seam — a table, an endpoint, a component, a client. Done means that seam exists. Nobody can walk it yet.

_Avoid_: task, ticket (when used as if those were the unit of progress).

Vertical slice. A narrow, complete path from a person’s intent to an observable result. It touches every technical layer that path needs, and only as much of each layer as the path needs.

_Avoid_: feature (too fat), story (too vague unless it names the path). See vertical slice.

Prototype. Throwaway code that answers one question. You keep the verdict. You do not keep the code on main.

_Avoid_: spike (when used as if it were the first product ticket). See tracer vs prototype.

Tracer. A lean, complete path through the real product. You keep it and thicken it. Feedback comes from firing under real conditions.

_Avoid_: walking skeleton (related, later). See tracer vs prototype.

Verification

Test list. Scratch notes of the cases you expect to cover. Analysis, not test code.

_Avoid_: suite (when the cases are still notes). See one failing test.

One failing test. The first automated check of a tracer, written so it fails before any product code exists.

_Avoid_: red (until the colour is defined in the lesson). See one failing test.

Only enough to pass. The product change after one test is red. The test file does not change. Cases still on the list are not implemented yet.

_Avoid_: make it pass (when that means editing the test or building the rest of the list). See only enough to pass.

Specifying

Fit criterion. The measurement attached to a requirement that makes it testable: what you would observe if it were false. Robertson & Robertson’s term.

_Avoid_: acceptance criteria (when they are adjectives with no measurement). See criteria that can fail.

Question. A case where nobody present knows the right outcome. Not a weak criterion — a different thing, and never delegated as if it were one.

_Avoid_: edge case, TBD (both hide the fact that a decision is missing). See criteria that can fail.

Key example. A small, boundary-chosen case that carries information a human can criticise. Chosen instead of exhaustive variations.

_Avoid_: test case (when the point is shared understanding, not coverage). See criteria that can fail.

Terms enter here after they have been practised, not when first named. Sources: RESOURCES.md.
