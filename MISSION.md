# Mission: Full-stack AI Engineer

## Why
I want to stop being a ticket-guided implementer and become someone who can independently design, build, review, deploy, operate, and evolve real AI-enabled web products. When this works, I can take an ambiguous product problem through to a running, observable, maintainable system in my target stack — and I can direct coding agents so the software they produce is reliable and verifiable, not just generated.

## Success looks like
- I can take a real user problem, bound a vertical slice, and ship it as a working path through UI, API, data, and (when relevant) an AI capability.
- I can review my own and an agent's work against explicit acceptance criteria, tests, and architecture constraints — and say what is not yet safe to ship.
- I can deploy and operate that slice: environments, logs/metrics, failure modes, cost, and rollback.
- I can evolve it: change the design when the problem shifts, without treating the first implementation as sacred.
- I can tell which decisions need my judgment and which I can safely hand to an agent.

## Constraints
- Professional background is .NET Core / C#, largely ticket-guided. Do not assume mastery of any capability group.
- Target implementation stack: .NET Core / C#, Python, TypeScript, React / Next.js, SQL and relational databases.
- Teach transferable engineering foundations and principles, not framework trivia — and not lesson-shaped practice paths the learner cannot fit into real work.
- Lessons prioritise clear foundational judgment (what to demand, what to reject, what to hand to an agent). The learner owns practice: experiments and labs on their own code, outside the lesson.
- Knowledge must be grounded in cited sources. In-lesson checks stay light (spot a wrong model, name a principle); do not turn lessons into a guided TDD/coding workout.
- Use a realistic example in the target stack when it reduces abstraction.
- Include trade-offs and failure modes only when they serve the current foundation.
- The ordered foundations map lives in `ROADMAP.md`. It is a compass, not a contract — pull lessons forward when real work demands it.
- With agentic tools, foundations matter more: know the principles well enough to direct and review agents; practice elsewhere builds fluency on that base.

## Out of scope
- Framework-feature tours (the latest Next.js API, EF Core trivia, LangChain recipes) except as needed to practise a foundation.
- Collecting certificates, interview-puzzle grinding, or becoming a research scientist.
- Building a large product before the foundations that make it reviewable and operable.
